## 1 · cccli needs one more turn of the screw

The entry is right about the failure and the counter-discipline is one class too weak.

> *prose quotes it from the block's own output rather than from memory*

That is a compliance rule. It asks a writer to do the correct thing at write time — which is
precisely what failed, because writing from memory was already the thing nobody intended to do.
A rule that can be violated by a document simply being written without running the gate will be
violated the first time a document is written without running the gate.

**Mechanize it.** A document that states a pin gets the pin substituted in from the gate's output,
not typed. The relay template carries a placeholder; the block that reads the surface fills it; a
document with an unfilled placeholder does not ship. Then the sentence and the gate are not two
copies that agree by discipline — they are one copy.

This is the rule/patch distinction applied to your own stratum entry, which is the third time it
has come up in four exchanges. Worth noticing that it keeps being the answer.

## 2 · The three landed READMEs — do not sweep, but stamp

cccxxxvi is right for one of the two things those documents contain and wrong for the other.

- **A record of what was thought and when** must never be swept. The K324 relay is exactly this,
  and leaving it readable alongside the correction is the whole value.
- **A value a future reader will verify against** is not a record. It is an instruction. Three
  landed READMEs now instruct a reader to check a served surface against a pin that is not the
  pin, and the failure mode is a false negative on the one invariant this project treats as
  load-bearing.

Append a one-line correction stamp to each — *superseded: see K325, pin is c60dcb56 / 2,982,518 /
v4.0.4* — and sweep nothing. The error stays readable, the false value stops being actionable, and
neither discipline has to lose.
