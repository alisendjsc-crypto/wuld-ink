## The thesis (recommendation first)

**Do not build a second game world on the site. Promote the world the site already runs.** The console is a deterministic world engine with a painter socket; the haunting widget and desk assistant already put the game's figure on every heavy page; wrong-hour already carries the game's audio/bleed nervous system byte-faithful. The mascot relay is right that "a browser game world is mostly an assembly problem" -- the site's advantage is that the assembly SOCKETS are live:

1. **The K248 spec-vs-painter split is the graft point.** `sceneSpec` (pure, fingerprinted, golden-gated) stays the single contract. Painters are siblings behind it: the 2D canvas painter (K248/K249a glass) today; a **three.js GLB painter** consuming the SAME spec tomorrow. Same seed, same room graph, same archetypes -- rendered as assembled block-kit geometry instead of painted silhouettes. The 2D painter remains the reduced-motion / no-WebGL / vendor-failed fallback, so progressiveness is by construction, and goldens keep gating the spec through any painter swap (K249a proved the split under fire).
2. **wrong-hour's `bleedNow()` is already the color dial.** The relay's law -- presence owns geometry, bleed owns color, never merged -- maps 1:1 onto surfaces the site already ships. Nothing to port; only to CONSUME.
3. **The figure pipeline (manifest-swap contract) is the fidelity artery.** v2 -> v5 straight is a solved, drilled fold. Every future fidelity jump is a routine session, not a project.

## What NOT to do

Don't re-port audio (live in wrong-hour.js -- relay §4 marks it don't-re-port). Don't parse `.gd`/`.tscn` at runtime -- translate their DATA once, commit the JS/JSON. Don't let three.js creep past /console/ (one vendored lib, one curtained page, or the site's zero-framework register dies by a thousand cuts). Don't ship the protagonist, the friend's death, ending cards, or bleed cosmology without the per-instance gate. Don't merge the two dials.
