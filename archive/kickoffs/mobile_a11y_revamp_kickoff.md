1 — THE LOAD-BEARING INVARIANT: DESKTOP IS BYTE-INERT
Every layout/visual change this session makes must leave the DESKTOP render pixel-identical. Two enforcement mechanisms, BOTH required:
* STRUCTURAL (author-time): every layout/visual rule is authored INSIDE a mobile-scoped media query — `@media (max-width: <bp>)` for narrow layout, and/or `@media (pointer: coarse)` / `(hover: none)` for touch ergonomics (targets touch devices at any width, e.g. tablets). Existing desktop rules are NEVER edited — they are byte-held; you APPEND mobile blocks. The ONLY changes permitted OUTSIDE a mobile query are invisible a11y SEMANTICS (a skip-link anchor, ARIA attributes, alt text, landmark roles, heading-order/`label for=`), and only when they provably do not shift desktop layout.
* EMPIRICAL (gate-time): a DESKTOP VISUAL-REGRESSION gate. Render every touched page at desktop widths (≥1280 and 900) via the local Playwright serve (Chromium at /opt/pw-browsers), before vs after, and assert the screenshots are IDENTICAL — or differ only inside an explicit a11y-semantics allowlist (a focus ring you added, never a layout shift). This CATCHES any media-query leak the structural rule missed. It is the gate that makes "desktop untouched" a proof, not a promise.
Corollary: prefer NEW mobile-only CSS in the component's existing stylesheet (appended `@media` block) over any edit to a live desktop selector. If a desktop selector MUST change to enable a mobile fix, that is a desktop-affecting change — STOP and flag it for a §1b ruling; do not sneak it in.
